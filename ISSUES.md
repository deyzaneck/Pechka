# Задачи разработки (Issues) — Хлебный Путь

Ниже представлен перечень задач (tracer bullets), разделяющий разработку на вертикальные срезы от слоя БД до Compose UI и тестов.

---

## Issue 1 (HITL): UI/UX Проектирование утреннего экрана округления хлеба
- **Тип:** HITL (Human-in-the-loop)
- **Блокирует:** Issue 4
- **Покрываемые User Stories:** US1, US2, US3, US4, US5, US6
- **Что сделать:** Спроектировать макет и интерактивный прототип интерфейса для утреннего экрана округления под разрешение 360x640. На экране должны быть: блок выбора направления округления (В большую / В меньшую сторону), счетчик штук излишка/дефицита (баланс округления), плотный список точек с крупными кнопками `[+]` и `[-]` (высота не менее 48dp) и кнопка «Начать рейс» (активна только при балансе = 0). Должно быть визуально понятно, что количество Хлеба на точке может быть уменьшено до 0.
- **Критерии приемки:**
  - Наличие интерактивного макета, проверенного на узких экранах.
  - Тач-зоны всех интерактивных элементов имеют размер >= 48dp.
  - Отсутствие перегруженности интерфейса.

## Issue 2 (AFK): Проектирование и создание локальной БД (Room DB & Entities)
- **Тип:** AFK (Away-from-keyboard / Автономно)
- **Блокирует:** Issue 4, Issue 5, Issue 7
- **Покрываемые User Stories:** Технический фундамент
- **Что сделать:** Описать Room-сущности `Point`, `Order`, `Payment` и связи между ними. Написать DAO-интерфейсы для:
  1. Чтения точек маршрута.
  2. Обновления количества хлеба в заказе.
  3. Записи транзакций оплаты.
  4. Удаления оплаты при переоткрытии точки.
  5. Сброса рейса (удаление всех оплат, сброс статусов в "PENDING").
  6. Добавления новой точки в базу.
- **Критерии приемки:**
  - База данных Room скомпилирована без ошибок.
  - Написаны Unit-тесты для DAO, проверяющие каскадное удаление, добавление новых точек, сброс рейса и удаление оплаты при переоткрытии.

## Issue 3 (AFK): Бизнес-логика калькулятора округления (Core Logic)
- **Тип:** AFK
- **Блокирует:** Issue 4
- **Покрываемые User Stories:** US1, US2, US3, US5
- **Что сделать:** Разработать чистый Kotlin-класс `BreadRoundingCalculator`, не завязанный на Android SDK. Логика должна рассчитывать:
  1. Суммарный заказ хлеба в штуках и лотках на рейс.
  2. Необходимость округления (если лотки дробные).
  3. Объем излишка/дефицита в штуках в зависимости от выбранного направления.
  4. Текущий баланс округления в процессе поштучного перераспределения по точкам (допускается урезание до 0).
- **Критерии приемки:**
  - Покрытие Unit-тестами 100% логики калькулятора (включая крайние случаи, когда суммарный заказ изначально кратен 16).

## Issue 5 (AFK): Главный экран рейса (Список точек в виде аккордеона) с функцией переоткрытия
- **Тип:** AFK
- **Блокирует:** Issue 6
- **Взаимные блокировки:** Заблокировано Issue 2, Issue 4
- **Покрываемые User Stories:** US7, US8, US10
- **Что сделать:** Реализовать главный экран со списком точек в их порядковой последовательности. Каждая карточка точки должна представлять собой аккордеон. При клике на карточку она плавно раскрывается вниз, показывая детали заказа (Хлеб в шт./лотках, Лаваш в шт., Итого к оплате) без перехода на новый экран. Добавить кнопку «Переоткрыть точку» для выполненных точек (`COMPLETED`), которая сбрасывает статус на `PENDING` и удаляет оплату.
- **Критерии приемки:**
  - Аккордеон раскрывается/сворачивается по клику на область карточки.
  - Каждая карточка имеет четкий статус: "PENDING" (серый фон/иконка ожидания) или "COMPLETED" (зеленый фон/галочка).
  - Нажатие на «Переоткрыть точку» сбрасывает статус в БД и обновляет UI.
  - Верстка адаптивна под ширину 360dp.

## Issue 6 (AFK): Ввод оплаты и закрытие точки в аккордеоне (Валидация и Частичные оплаты)
- **Тип:** AFK
- **Взаимные блокировки:** Заблокировано Issue 5
- **Покрываемые User Stories:** US9, US10
- **Что сделать:** Добавить внутрь раскрытой карточки точки блок оплаты: поле ввода суммы, переключатель типа оплаты (Наличные / Карта) и кнопку «Закрыть точку».
  1. Блокировать закрытие, если сумма оплаты равна `0` (оплата в долг запрещена).
  2. Если сумма оплаты `> 0`, но отличается от расчетной стоимости заказа, показывать всплывающее предупреждение ("Сумма отличается от чека. Закрыть точку?"). При согласии водителя закрывать точку.
  3. Для закрытых точек выводить фактически оплаченную сумму, а расчетную сумму показывать рядом в скобках, например: **Оплачено: 1 500 руб. (Чек: 1 800 руб.)**.
- **Критерии приемки:**
  - При нажатии на «Закрыть точку» в таблицу `payments` пишется транзакция, а статус точки в `points` обновляется на "COMPLETED".
  - Все правила валидации оплат работают корректно.

## Issue 7 (AFK): Панель управления (Создание/Сброс рейса и добавление магазинов)
- **Тип:** AFK
- **Взаимные блокировки:** Заблокировано Issue 2
- **Покрываемые User Stories:** US11, US12
- **Что сделать:** Реализовать отдельный экран настроек/меню с крупными кнопками:
  1. «Создать рейс» (инициализирует новый рейс).
  2. «Сбросить рейс» (сбрасывает все статусы текущего рейса в `PENDING` и очищает оплаты).
  3. Раздел «Магазины», где выводится список магазинов с формой добавления нового магазина (Поле ввода названия точки, поле ввода порядкового номера доставки).
- **Критерии приемки:**
  - Добавление новой точки мгновенно записывает ее в базу.
  - Сброс рейса очищает текущий прогресс доставки в БД и перенаправляет водителя на главный экран со статусами PENDING.
